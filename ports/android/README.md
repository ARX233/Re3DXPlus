# Android port source snapshot

This is a development snapshot, not a ready-to-build or tested release. The MIT license covers the port source only; game material is not included or licensed by it. Obtain and use any required game inputs only with appropriate rights, locally and privately. Do not commit generated resources, archives, keys, save files or build output. The local ignore rules are a safety aid, not a substitute for reviewing staged changes.

## Android 1.31 snapshot

This source snapshot contains the 1.31 adjustable joystick deadzone, fixed/floating joystick center, separate accelerator and shift layouts, and main race HUD layout controls. The resource installer can reuse an unchanged package and update registered resources per file; it preserves saves, extra files and locally modified files. An interrupted update needs the same packaged ZIP to resume, and an old resource version is not immediately available for rollback. The installer assumes cooperating application processes and excludes concurrent modification by root, ADB or other non-cooperating writers; actual device and power-loss behavior require testing.

App-owned diagnostic event logging is disabled in this snapshot. `DEBUG_LOG=1` is unsupported and the build script rejects it. Some diagnostic source and host tests remain for development; they do not establish an available Android diagnostic build. Android system logs may still exist independently.

## Build status and prerequisites

Android SDK (build-tools and platform), NDK, JDK, Python 3 and tools required by the asset generators are needed; some generators need Pillow, capstone, unicorn and c++filt. `build_android.sh` requires explicit `ANDROID_HOME`, `JAVA_HOME`, `SIGNING_KEYSTORE`, `APP_ICON`, and `CARD_RESOURCES`. Signing passwords are requested interactively by apksigner. The script never installs or transfers to a device.

**The source snapshot is incomplete for compilation.** Generated game-derived headers, `src/phys/phys_rc.c` and data files are deliberately absent. The generic generator script requires an explicit original root but intentionally stops before writing because `tools/weartexts.py`, `tools/titledb.py` and the physics roots list are excluded: they contain or may contain original-derived data. The remaining generators alone have not been verified to recreate every missing file. Newer meter, story cut-in and racing lamp inputs require separate local preparation; no complete generation procedure has been validated. `tools/time_texture.py` can generate the time texture header from a user-supplied 64×32 PNG; the image itself is not included. The Vulkan source directory includes 31 public baseline shaders and two derived from this project's SSAO/blur sources; `src/vkgl_spv.c` is generated locally by `tools/vkglsl.py` during the build. Do not upload generated outputs.

Once these gaps are addressed locally, run `./build_android.sh` with the explicit inputs above; `VK=0` selects the GLES path. To label a compatible 1.31 test package, set `VERSION_CODE=35` and `VERSION_NAME=1.31-test` (or `1.31-gles-test` for GLES). This is a description of the intended process, not a claim a clean checkout builds. An isolated build with local generated inputs has compiled and linked; device verification remains necessary.

For builds intended to stay on an external macOS APFS image, `tools/external_snapshot_build.py --help` describes an opt-in, fail-closed entry point. Prepare and independently review a complete Android source snapshot on the image first; the tool's generated manifest detects later changes but does not establish provenance or rights. It does not combine a snapshot with the current working tree or generate missing original-derived inputs. The caller supplies the external mount, its sparsebundle, a workspace on that mount, a new manifest, version, expected signing-certificate digest, independently reviewed `--expected-game-data-sha256`, toolchain and asset paths. The expected data hash must be selected independently before the build; hashing whichever archive was selected is not sufficient review. It checks the volume and reviewed script pins, then builds in a separate image-resident copy with external output and temporary directories. The current 1.31 build script differs from the helper's pinned script, so the helper deliberately refuses this snapshot until the script is independently reviewed and its pin is deliberately updated. It checks ZIP integrity, alignment, package, version, signing certificate and explicitly supplied asset bytes; the icon and optional implicit fallback assets are not independently compared. Signing may be interactive or use explicitly supplied environment variables; no device operation is requested. The helper has mock tests and was used for earlier builds. It is not a sandbox: all snapshot code, inputs and tools must be trusted, and third-party system caches or concurrent mount changes are not fully controlled. A mounted image with ownership disabled or without encryption is not a private storage boundary; do not place signing keys in a snapshot.

The finish-distance display uses a locally generated `CARD_PAGES_BIN` sidecar; the existing card-page bank must be extended with the original animation assets using `tools/finish_pack.py`. Some supplied `cons_p_last_0`–`9` source images all depict zero, and the supplied metre image has a red border. The generator substitutes the existing menu distance digits and removes only the red outer border; the typeface is an approximation, not a verified restoration. For an already-extended bank, `python3 tools/finish_pack.py --repair MENU_OR_DATA_ZIP EXISTING_BANK NEW_BANK` creates a separate corrected bank without overwriting the input. Backfire uses a matched `BACKFIRE_WPK` and `BACKFIRE_BFX` pair generated locally with `tools/backfire_effect_pack.py`. The effect is disabled when its pair is absent or invalid; the local animation interpolation is approximate. Some character models lack the original `MUFFLER1/2` nodes and are reported rather than assigned invented outlets. The original-derived data files must not be committed.

Android tire tracks use original per-wheel display matrices and effect opacity read from the physics engine, the original 30-vertex FIFO per wheel, and a locally generated `tiretrack.wpk` at the game-data ZIP root. Generate it from the verified original `data/sprite/tirepattern.tga` with `tools/stage/pack_tire_track.py`, add it to a new reviewed ZIP, and commit neither original data nor generated assets. Missing or corrupt data disables the visual effect. Sampling once per simulation tick, 4-bit texture quantization and GPU behavior are not proven identical to the arcade; the effect does not modify driving physics.

The IGB2 vertex-color correction in `tools/stage/scene.py` affects newly generated assets only; existing installed WPK files are not rewritten. Rebuild and validate the affected stage data separately, keeping existing saves and data intact. For local story-car WPKs, `tools/fix_characar_wheels.py --source-engine-order` applies the statically inferred original DXT channel conversion only after checking the source image and exact encoded bytes; it writes a separate directory and reports any unknowns. The user reports that an earlier corrected build displayed properly on their phone; the subsequent 1.20 package regressed by selecting an older data ZIP. The 1.21 resource correction has not yet been confirmed on a device.

The race HUD's minimap needs one `WNV1` file per city (`navi.bin`, `navi_oosaka.bin`, `navi_hakone.bin`, `navi_nagoya.bin`, `navi_fukuoka.bin`) in the data directory. `tools/navipack.py` builds them from the original `data/minimap/*.igb` and the original executable alone; older packages that only carried `navi.bin` show an empty map box in the other cities. A failed city load now keeps the previous map in memory but refuses to draw it for the wrong city, logs the reason, and retries on the next explicit request.

The story mode's day/night card is a port extension, not an asserted arcade behaviour: the choice is asked after the rival is picked, stored separately in `story_timezone`, and no longer follows the Time Attack setting (`timezone`). Time Attack keeps its own remembered choice.

The recompiled physics inherits one unbounded walk from the original code: `CAreaProcessorJunction::MoveToPrev` decrements a section index without a lower bound, so index 0 reads `area_array[-1]`. `tools/recomp/guard_sections.py` (run by `build_phys.sh` and both port build scripts) clamps that single function to the first known section; it is idempotent and fails loudly on unexpected input. This removes one crash class seen in a device tombstone; it is not a complete proof that every reported crash had that cause.
