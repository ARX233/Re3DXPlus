# Selective Android sync

The Android source is based on the pre-merge port, not a wholesale copy of upstream. The network client, embedded host and Python server follow upstream `76e1558` (WV1). The application advertises upstream profile `W/168` experimentally to attempt interoperability; matching that profile does not establish compatible race physics. Real cross-version races, packet loss and disconnects require device testing. WV1 does not provide the prior WV2 abort, done and acknowledgment guarantees. In the unmodified upstream host, losing the initial GO messages can leave one peer in the lobby or cause repeated START requests to create different race IDs; a host disappearing during loading may not be reported until after the loading timeout. Do not treat a successful local smoke test as evidence these loss and disconnect cases are safe.

The optional chapter selector is a testing mode and does not advance normal story progress. The story carryover code preserves the existing local memory bridge rather than mixing it with upstream's different serialization implementation. Generated physics is not checked into the repository. The previously built 1.24 source used for verification has SHA-256 `a4d98adbe6b3bc8a86b09adc9f7af5c97a78a3298126bc0c1b0d18fb8f1ee26b`; its matching `phys.img` has SHA-256 `5790b205045807181ab3931c9583b5652fbe9b8e7af8b9c1680c00325db0bd4`. The unmodified production build does **not** automatically add this bridge to freshly generated physics. Verify the actual private generated file with `python3 ports/android/tests/test_story_carry_real_hooks.py /path/to/phys_rc.c` before building; an unpatched generated file leaves this experimental repair disabled. The host test does not establish that episode 35 has been fixed on a device.

The actual valve and backfire audio cues additionally need `sound/valb1.wav`, `sound/valb2.wav`, `sound/valb3.wav`, `sound/backfire1.wav`, and `sound/backfire2.wav` from the caller's original game files. They are not included in the repository; older data archives may lack the last two. Tire marks additionally require the verified `tiretrack.wpk` at the data root, generated from the original `tirepattern.tga` using `tools/stage/pack_tire_track.py`. The checked older archive lacks both that file and the two backfire sounds. Existing story-cut-in, card and backfire visual sidecars must be supplied as required by the selected build. Never overwrite the player's saves or the original resource archive while preparing a build.

The restored 1.24 no-log startup does not create app-owned `log.txt` or `perf.log`, enable the optional event collector, or set a Vulkan missing-shader output directory. Use the default `DEBUG_LOG=0`; this snapshot rejects `DEBUG_LOG=1` before building. This is not a guarantee that Android stderr or logcat is silent. The generated private code and all assets are excluded from Git.
